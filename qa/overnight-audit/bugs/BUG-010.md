# BUG-010 — Homepage axe violations: invalid ARIA on AI Edit chips + claim paragraph

- **Severity:** P3 (1 critical, 1 serious — both in static homepage markup)
- **Feature:** Homepage (AI Edit demo, hero Hinglish claim)
- **Route:** `/`
- **Tool:** axe-core 4.12.1, local dev
- **Files:** `apps/frontend/src/components/home/AiEditDemo.tsx:229`, `apps/frontend/src/components/home/Sections.tsx:168`

## Findings (axe-core, home page)
1. **`aria-allowed-attr` — CRITICAL, 5 nodes.** The AI Edit demo style chips are
   inert `<span aria-pressed={picked}>`. `aria-pressed` is not allowed on a generic
   span. The chips are narration, not controls (the demo's own comment says so).
2. **`aria-prohibited-attr` — SERIOUS, 1 node.** The Hinglish claim is
   `<p data-hero="claim" aria-label="95% Hinglish caption accurate...">`.
   `aria-label` is prohibited on a `<p>` (implicit role "paragraph" cannot be named).
3. **`color-contrast` — SERIOUS, 10 nodes.** Muted look-tag pills (`#B4B4AA` on
   `#232320`, 11px) in the homepage looks gallery. NOT fixed here — the muted
   palette is the owner's chosen design; see Recommendation below.

## Evidence
- `qa/overnight-audit/evidence/axe-home-detail.json` (full node HTML + failure summaries)
- `qa/overnight-audit/evidence/viewports-axe.json` (axe section)

## Fix (1 + 2 only)
1. Remove `aria-pressed={picked}` from the demo chips. They stay inert spans —
   the owner's open call (live buttons vs visibly-inert) is untouched; if he
   chooses live later, they become real `<button>`s and `aria-pressed` returns.
2. Add `role="group"` to the claim `<p>` so the `aria-label` is permitted.
   No visual change; the `hinglishClaim.test.tsx` assertion on the aria-label
   still passes unchanged.
3. Color-contrast: RECOMMENDATION, not a fix. Brightening the tag pills to pass
   4.5:1 changes the muted palette everywhere that tone is used. Owner's call.

## Regression test
Re-run axe on `/` after the fix: `aria-allowed-attr` and `aria-prohibited-attr`
must be gone. (`color-contrast` remains as a known open item.)
