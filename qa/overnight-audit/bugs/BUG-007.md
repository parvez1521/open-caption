# BUG-007 — Homepage intro logs a React duplicate-key warning (word "on" twice)

- **Severity:** P3
- **Feature:** Homepage intro loader
- **Route:** `/`
- **Browser/viewport:** headless Chromium, 1440×900 (local dev); reproduces on every home load
- **File:** `apps/frontend/src/components/home/Loader.tsx:25,131`

## Steps to reproduce
1. Open `/` in a browser with the console open.
2. Watch the intro loader play.
3. The console shows the React warning twice: "Encountered two children with the same key, `on`. Keys should be unique so that components maintain their identity across updates."

## Expected
No console errors or warnings on a clean home load. Every word span has a unique key.

## Actual
React logs the duplicate-key warning twice per home load (reproduced in 3 separate CDP probe runs: home probe, home-content probe, dedicated dupkey probe). React's own text says the behaviour is unsupported and children "may be duplicated and/or omitted".

## Evidence
- `qa/overnight-audit/evidence/console/dupkey-home.txt` — full console capture (2 warnings, key `on`).
- `qa/overnight-audit/evidence/screenshots/home-probe.json` — console messages from the viewport probe.
- `qa/overnight-audit/tests/e2e/qa-probe-dupkey.mjs` — repro probe.

## Root cause
`Loader.tsx:25`: `WORDS = ["Every", "word,", "on", "screen,", "on", "time."]` — the word "on" appears twice. `Loader.tsx:131` renders the words with `key={w}`, so two spans share key "on".

## Recommended fix
Use the index in the key: `key={`${w}-${i}`}` (one line). No visual change — the words, order, and animation delays are untouched.

## Regression test
`apps/frontend/src/components/home/__tests__/loader.test.tsx` — renders the Loader with `console.error` spied on and asserts no duplicate-key warning is logged, and that all six word spans render in order.

## Runtime repro: confirmed (local dev CDP, 3 runs)

## Fix applied (2026-11-14 ~03:20 IST, this branch)
- `Loader.tsx:131`: `key={w}` → `` key={`${w}-${i}`} ``. One line. No visual change.
- Regression test `loader.test.tsx` verifies the fix two ways: it FAILS on the old key (rc=1, confirmed by temporarily reverting) and PASSES on the new key (rc=0, 1 test, 6.6s single-file run).
- Full-suite re-verification runs at the end of the mission (Phase 11).
