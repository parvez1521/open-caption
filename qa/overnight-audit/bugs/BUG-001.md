# BUG-001 — Video duration limit bypassed by omitting the client probe

- **Severity:** P2
- **File:** `apps/frontend/src/app/api/v1/projects/[id]/videos/route.ts:27`
- **Also:** `packages/shared/src/api-schemas.ts:28` (probe optional), `apps/frontend/src/app/api/v1/videos/[id]/complete/route.ts:22-24` (no duration check)

## Expected

The plan duration limit (Free 5 min, Starter 30 min, Growth 60 min, Pro 3 h — `packages/shared/src/plans.ts:27-31`) is enforced server-side for every upload, so a caller cannot register a longer video by shaping the request.

## Actual (code behaviour)

The server checks duration only when the client volunteers a probe:

```ts
if (body.probe && body.probe.durationMs / 1000 > limits.maxDurationSec) {
  throw new ApiFailure("LIMIT_EXCEEDED", ...);
}
```

`probe` is optional in the request schema (`CreateVideoBody`, `api-schemas.ts:28`: `probe: ProbeSchema.optional()`), so a request with no `probe` skips the check entirely. The follow-up step (`videos/[id]/complete/route.ts:22-24`) only verifies the stored object exists and records its real size — it never measures or checks duration. The only remaining enforcement is client-side (`features/upload/prepareVideo.ts:92-93` throws `TOO_LONG` in the browser), which a direct API caller bypasses.

## Evidence

- `apps/frontend/src/app/api/v1/projects/[id]/videos/route.ts:27` — duration check guarded by `body.probe &&`.
- `packages/shared/src/api-schemas.ts:28` — `probe: ProbeSchema.optional()`.
- `apps/frontend/src/app/api/v1/videos/[id]/complete/route.ts:22-24` — `objectSize` checked for existence only, no duration comparison.

## Root cause

Duration is treated as client-probed metadata rather than a server-verified property of the stored object. The server trusts the absence of a probe as "no limit applies".

## Recommended fix

Make `probe` required for non-local uploads, or measure duration server-side at complete time (e.g. probe the stored object with ffprobe / read duration from the upload) and reject over-limit videos before marking them uploaded. Keep the client-side check as a UX pre-check only.
