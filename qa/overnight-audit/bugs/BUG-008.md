# BUG-008 — /transcribe shows the raw fetch error when the model download fails

- **Severity:** P3
- **Feature:** Standalone Transcribe
- **Route:** `/transcribe`
- **Browser/viewport:** headless Chromium, local dev (offline to Hugging Face)
- **Files:** `apps/frontend/src/features/transcribe/standalone.ts:263`, `apps/frontend/src/features/transcribe/whisper.worker.ts:313-315`

## Steps to reproduce
1. Open `/transcribe` as a guest.
2. Upload any valid video with speech (e.g. `v07_silence_720x1280.mp4`, `v10_corrupt.mp4`).
3. Tap Transcribe while the browser cannot reach Hugging Face (offline / blocked network).
4. After ~5s the page shows a red alert: **"Failed to fetch"**.

## Expected
A plain-language message, like the Studio already shows for the same failure:
"Setup didn't finish because the connection dropped. Check your internet and try again."
(`features/transcribe/session.ts:477` maps `/network|fetch|load failed|failed to fetch/` to that sentence.)

## Actual
The raw `TypeError` message from the model download is shown verbatim. A user
with no connection gets a programmer's error and no guidance.

## Evidence
- `qa/overnight-audit/evidence/transcribe-probe.json` — v10 + v07 `transcribeTimeline[0].alert: "Failed to fetch"`.

## Root cause
The worker's run catch (`whisper.worker.ts:313`) posts `err.message` verbatim and
`standalone.ts:263` rejects with it verbatim. The Studio session maps the same
message to a friendly sentence, but the standalone path never does.

## Recommended fix (standalone path ONLY)
In `standalone.ts` error handling, map a network-ish worker message
(`/network|fetch|load failed|failed to fetch/i`) to:
"Couldn't download the transcription model. Check your connection and try again."
Do NOT change the shared worker catch — the Studio session maps the raw message
itself, and a friendly message from the worker would fall through its regex to
the generic "Something interrupted the captions" line (worse for Studio).

## Regression test
Drive `runStandaloneTranscribe` with a mocked Worker that posts
`{type:"error", message:"Failed to fetch"}` and assert the rejection message
is the friendly sentence. (Check existing standalone/worker test mocks first.)

## Fix applied (2026-11-14 ~04:15 IST, this branch)
- `standalone.ts` error branch: network-ish worker messages (`/network|fetch|load failed|failed to fetch/i`)
  map to "Couldn't download the transcription model. Check your connection and try again."
  Non-network errors pass through unchanged. Shared worker untouched (Studio maps the raw message itself).
- Regression tests in `__tests__/standalone-run.test.ts` (2 new, 8 total in file).
  Proves the fix: without it, the "Failed to fetch" test FAILS (1 failed / 7 passed);
  with it, 8/8 pass (single-file run 3.9s).
- **Live re-verified 2026-11-14 ~04:20 IST:** CDP /transcribe with v07 — alert now reads
  "Couldn't download the transcription model. Check your connection and try again."
  (was "Failed to fetch"). Evidence `evidence/transcribe-probe.json` (probe5 run).
